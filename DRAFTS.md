# Drafts

Here’s an interesting idea: Developers should go through a proficiency test before they are allowed to use LLMs to generate code. An AI driver’s license of sorts if you will.

It’s a bit similar to the level of apprenticeship that software houses would ask from junior engineers before they would get push or review access on a repository. Similarly before we allow somebody to unleash the code generating potential of a LLM, we should make sure they know for sure how to wield it safely.

Of course they can use an LLM to support them in learning and research all they want. They just can’t accelerate the brute force task of typing out solutions using one. It’s too tempting for somebody who doesn’t know enough.

There are reasons for both sides to want this arrangement.

Company

For the company it should be obvious by now that LLMs function as an amplifier. Those who are skilled can wield this and become even better and much more effective. Those who aren’t can wield the tool to pretend they’re not as bad and paper over their gaps in knowledge and effective delivery.

Demands from the company side will always be infinite and being conscious of that should make it clear that the technology will always be abused. There will always be accountability and ownership gaps and ever increasing demands that will make it too tempting to just one shot your commitment for the week.

The company needs to be able to utilise the productivity increase of an LLM without allowing every engineer to destroy the coherence of the code base. This arrangement allows that by gating LLM usage and showing a clear path how to get there.

Engineer

For the engineer the equation is even more clear cut. Prompting a LLM and doomscrolling while you wait for the output to come back is a direct path to de skill yourself.

If you’re not adding any value in intent, knowledge and nous and not continuously increasing that value by using LLMs, you are active deskilling yourself. You need to be on top of the code and know exactly what’s happening. At a junior level that will be pretty much impossible. Just telling it to fix lint until it passes CI and then hope somebody else will approve it to merge is a losing proposition. It’s pure short term thinking and you will be out of a job in a couple of years from now.

If you need to generate the output, the best and most effective way to do that would be to leoarn how to touch type. The LLM has been considered to be a faster autotype anyway. No reason to use all this technology if you’re going to be at 100wpm anyway.

As a junior engineer you need to get to the point where you can use an LLM effectively and that will only happen if you use the technology diligently and reflectively to learn and to better yourself. If there’s no expectation that you will one shot out thousands of lines of code every day, you will get the space to do so and a somewhat clear path of how to get there.

A driver’s license for LLMs may not be a perfect solution but at worst I think it’d remove a lot of sharp edges for the new problems it introduces. Think about it next time you see a multi thousand line PR fly by where you know no human has looked at any of it.
